# SciLab 3D（理科虚拟实验室）——HarmonyOS 应用总体方案

> 版本：v1.0 | 日期：2026-10-14 | 平台：HarmonyOS NEXT (API 12+) / ArkTS

---

## 1. 产品定位

面向中学生与大学低年级学生的**理科 3D 虚拟实验室**` App，`覆盖：

| 学科域 | 中学阶段                                           | 大学阶段                              |
| --- | ---------------------------------------------- | --------------------------------- |
| 物理  | 力学（斜面、单摆、平抛、碰撞）、电学（电路搭建）、光学（透镜、折射、干涉）、热学（气体定律） | 电路分析（RLC）、刚体转动、波动与声学、近代物理（光电效应模拟） |
| 化学  | 酸碱中和、燃烧、沉淀反应、金属活动性、气体制备                        | 滴定分析、有机反应机理、电化学、萃取与蒸馏             |
| 生物  | 显微镜使用、细胞结构、光合作用、生态系统                           | 遗传学（孟德尔杂交）、微生物培养、酶动力学             |
| 通用  | 实验安全、仪器认知、测量与误差                                | 测量不确定度、数据线性回归、实验报告撰写              |

**核心价值**：危险/昂贵/耗时实验的零成本复现、可反复操作、参数可视化、自动生成实验报告。

## 2. 技术选型

| 层             | 选型                                      | 说明                                                   |
| ------------- | --------------------------------------- | ---------------------------------------------------- |
| 主体 UI         | ArkTS 声明式（ArkUI）                        | 首页/列表/设置/报告等全部原生                                     |
| 3D 渲染         | **Web 组件 + three.js**（Babylon.js 备选）    | 3D 场景跑在本地 WebView 内（rawfile 加载，离线可用），生态最成熟、3D 素材管线最短 |
| 物理引擎          | **cannon-es**（JS 刚体动力学）                 | 力学实验的刚体/约束/碰撞；three.js 深度集成                          |
| 电路求解          | 自研 **MNA 节点分析引擎**（TS）                   | 直流/交流稳态电路，支持 R/L/C/电源/仪表                             |
| 光学            | 自研**光线追踪器**（TS）                         | 透镜/反射镜/折射/干涉的 2D 剖面 + 3D 光路                          |
| 化学反应          | 自研**反应规则引擎**（JSON 配方 + 状态机）             | 反应方程式、颜色/沉淀/气体粒子特效                                   |
| 生物            | 3D 模型（glTF）+ 程序化动画                      | 细胞器、显微镜视野、生命周期状态机                                    |
| ArkTS ↔ JS 通信 | `javaScriptProxy` + `runJavaScript` 双向桥 | 原生 UI 控制 3D 场景，3D 场景回传数据                             |
| 本地存储          | RelationalStore（成绩/报告）+ Preferences（设置） |                                                      |
| 3D 资产         | glTF 2.0（Draco 压缩）+ 程序化几何               | 仪器模型自建或 CC0 素材库                                      |
| 后续演进          | 端侧 AI 助教、云同步、协作课堂                       | W9+ 阶段                                               |

**为什么选 Web 组件 + three.js 而不是纯 Native（XComponent + OpenGL ES）**：

1. three.js 生态（模型加载器、后处理、粒子、拾取）成熟，开发效率约为 Native 的 5-10 倍；
2. 模拟逻辑（物理/电路/反应引擎）与渲染在同一 JS 运行时内，无跨语言开销；
3. 本地 rawfile 加载，完全离线；
4. 性能瓶颈期（超大规模场景）再针对个别实验做 Native 化降级。

### 3.1 「实验包」机制（核心设计）

每个实验 = 一个**自包含实验包**，支持热插拔扩展、无需改主程序：

```
experiments/
  physics.inclined_plane/
    manifest.json        ← 实验元信息（学科/难度/器材清单/评分规则）
    scene.json           ← DSL：器材、初始位置、参数范围、约束
    script.js            ← 可选：实验特有逻辑（钩子函数）
    assets/              ← glTF 模型、贴图
```

**scene.json DSL 示意（斜面实验）**：

```json
{
  "apparatus": [
    { "id": "ramp",  "type": "mesh",  "asset": "ramp.gltf",
      "params": { "angle": { "min": 5, "max": 45, "step": 1, "default": 30, "unit": "°" } } },
    { "id": "block", "type": "rigid", "mass": { "default": 1, "unit": "kg" },
      "friction": { "default": 0.2 } }
  ],
  "sensors": [
    { "type": "stopwatch", "bind": "block.crosses", "x": 1.5 },
    { "type": "speedometer", "bind": "block.velocity" }
  ],
  "tasks": [
    { "goal": "测量不同倾角下的加速度", "record": ["angle", "time", "distance"] }
  ],
  "scoring": { "dataPoints": 5, "errorTolerance": 0.05, "reportRequired": true }
}
```

## 7. 后端服务设计（W9–W11 启用；首发离线版不依赖后端）

### 7.1 总体形态与选型

| 项    | 选型                                              | 理由                                                                              |
| ---- | ----------------------------------------------- | ------------------------------------------------------------------------------- |
| 架构演进 | **阶段一轻单体 → 阶段二按域拆分**                            | 前期用户量小，一个单体（NestJS）承载全部模块，省成本省运维；用户破万后再按域拆微服务                                   |
| 语言框架 | **Node.js + TypeScript + NestJS**               | 与 3D 实验引擎同为 TS，`scene.json` Schema 可在 Monorepo 中前后端共享同一份类型定义，实验包服务端校验与客户端加载天然一致 |
| 部署   | 华为云 ECS（2C4G 起步）+ RDS MySQL + Redis + OBS + CDN | 与 APP 备案接入商（华为云）保持一致，备案/服务器/域名一条链路打通                                            |
| 协议   | HTTPS REST（JSON）+ WebSocket（课堂实时）               | 统一响应 `{code, msg, data}`；断网时端侧全部功能不依赖服务端                                        |

### 7.2 服务模块

| 模块    | 核心职责                                                     | 启用阶段  |
| ----- | -------------------------------------------------------- | ----- |
| 认证服务  | 华为账号一键登录 / 手机号验证码；JWT 短期票据 + refresh token；角色（学生/教师/管理员） | W11   |
| 实验包分发 | 版本清单（含哈希+签名）、OBS 存储 + CDN 加速、客户端增量下载、下载统计                | W10   |
| 数据同步  | 学习进度/成绩/实验报告云备份；操作日志（op-log）追加式同步；冲突按 LWW + 时间戳          | W11   |
| AI 网关 | 聚合已完成备案的云端大模型 API；鉴权/限流/熔断/用量计费；内容安全过滤；审计日志              | W9    |
| 协作课堂  | 教师建班、下发实验任务、收取报告作业、批改；WebSocket 实时通知                     | W11   |
| 运营后台  | 实验包上架/审核、用户管理、数据看板（DAU/实验完成率/AI 用量）                      | W10 起 |

### 7.3 关键设计决策

**① 实验包分发协议（防篡改 + 增量更新）**

```
GET /api/v1/packs/manifest          ← 全量版本清单（含每个包的 version/hash/size/url）
GET /api/v1/packs/{id}/download     ← 302 至 CDN；客户端校验 SHA-256 后入沙箱
POST /api/v1/packs/{id}/report      ← 匿名安装统计（不关联用户身份，最小化收集）
```

**② 同步策略**：端侧 RelationalStore 为唯一事实源，云端是备份与多端媒介——断网无感，联网静默同步；报告文件（图片/PDF）走 OBS 直传预签名 URL，不占 API 带宽。

**③ AI 网关路由**：端侧三级路由的第三级入口；按用户配额限流（防刷），对模型返回做敏感内容过滤后透传；`ai_usage_logs` 记录 token 用量用于成本核算。

**④ 安全与隐私**：全链路 HTTPS；手机号等身份字段加密存储、展示脱敏；未成年人模式默认不采集任何个人信息（离线版即此形态）；遵循《个人信息保护法》最小必要原则。

### 7.4 核心数据模型

```
users(id, role, nickname, phone_enc, created_at)
devices(id, user_id, model, last_sync_at)
experiment_records(id, user_id, pack_id, score, duration, finished_at)
reports(id, record_id, obs_key, format, created_at)
classes(id, teacher_id, name, invite_code)
assignments(id, class_id, pack_id, deadline)
submissions(id, assignment_id, student_id, report_id, grade)
pack_versions(id, pack_id, version, hash, size, status, published_at)
ai_usage_logs(id, user_id, model, tokens_in, tokens_out, created_at)
```

### 7.5 代码组织与成本

- Monorepo：`server/`（NestJS）与客户端 `rawfile/web/engine/` 共享 `packages/schema/`（实验包/桥消息的 TS 类型与校验）
- 初期月成本：ECS 2C4G ≈¥100 + RDS ≈¥100 + OBS/CDN/带宽按量，**约 ¥200–300/月**；用户量上来后弹性扩容

## 8. 关键风险与对策

| 风险                   | 对策                                  |
| -------------------- | ----------------------------------- |
| WebView 3D 性能不足（低端机） | 降级策略：减粒子数/关阴影/降分辨率；个别重实验后期 Native 化 |
| three.js 体积较大        | Draco 模型压缩 + 实验包按需加载，首包只含 W2 力学实验   |
| 化学反应真实性              | 采用"教材级近似"：只模拟可见现象 + 定量数据曲线，不追求分子级仿真 |
| 端侧模型包体与内存            | 模型不进首包，设置页可选下载至沙箱；实验台页按需加载、退出释放     |
| ArkTS 与 JS 类型不一致     | 桥协议统一 JSON Schema，双向消息带 `msgId` 应答  |
| 大学实验专业性              | 每个大学实验包增加"教师审校"标记位，内容可校对迭代          |

## 11. 多端策略（**PC 为主线**，HarmonyOS 为副线）

> 2026-10-14 调整：用户确认主要需求为 PC 应用。主线反转——PC 版立即启动；HarmonyOS 版保留已完成的 W1 成果（三 Tab + 3D 实验台 + 桥验证，已编译通过），引擎稳定后一次性移植。

**核心结论**：3D 实验引擎、实验包、桥协议均为平台无关的 Web 技术，两端共享同一套引擎，仅 UI 壳层按平台各自实现。

| 层 | PC 版（主线） | HarmonyOS 版（副线） |
|----|---------------|----------------------|
| UI 壳层 | **Vue 3 + Vite + TypeScript**（侧边栏布局，键鼠交互） | ArkTS 原生（W1 已完成） |
| 宿主容器 | **Tauri 2（Rust 壳 + WebView2）**；开发期直接浏览器运行 | ArkUI Web 组件 |
| 3D 引擎/实验包/桥协议 | `pc/src/engine/` | `entry/src/main/resources/rawfile/web/`（同一套代码，后续 Monorepo 统一） |

| 项 | 说明 |
|----|------|
| 桥的差异 | PC 上 UI 与引擎同在浏览器运行时，"桥"退化为同层事件总线（更简单）；Tauri 壳只负责窗口、本地文件、导出 PDF |
| 开发模式 | `npm run dev` 浏览器直接开发（**无需 Rust**）；`tauri dev/build` 出桌面安装包（需 Rust 工具链） |
