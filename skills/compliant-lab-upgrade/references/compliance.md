# SPDX 合规分级与红线

## 三档分级

| 档位 | 常见 SPDX | 复用代码 | 复制资源/文案 | 借鉴算法思想 | 归属要求 |
|---|---|---|---|---|---|
| 宽松 | MIT、Apache-2.0、BSD-2/3-Clause、ISC、Zlib、0BSD | 允许 | 允许 | 允许 | 保留版权声明；Apache-2.0 还需 NOTICE 与变更说明 |
| 弱 Copyleft | LGPL-2.1/3.0、MPL-2.0、EPL-1.0/2.0、CDDL | 有条件（动态链接 / 文件级） | 通常不允许 | 允许 | 修改部分需同许可开源，且有链接/源码提供义务 |
| 强 Copyleft | GPL-2.0/3.0、AGPL-3.0、SSPL、CeCILL、EUPL | **禁止** | **禁止** | 允许（公开数学定义与论文不受著作权保护） | 分发即触发同许可与源码提供义务 |
| 内容型 | CC BY / CC BY-SA / CC BY-NC | 不适用 | 按条款 | 允许 | 署名、相同方式共享、非商业限制需逐条核对 |

> **本工作流的默认策略比法律下限更严**：即便宽松许可允许复制代码，也**只取思路并列名致谢**。这样可以从根上消除归属遗漏、许可证头丢失、后续再许可争议。

## 什么算「只借鉴思想」

| 允许 | 不允许 |
|---|---|
| 教科书/论文中的数值方法定义（RK4、Dormand-Prince 系数、LU 分解、MNA、BKT 公式） | 把对方源码翻译/改写/换变量名 |
| README 里描述的架构分层与数据流 | 复制目录结构命名 + 接口签名 + 注释 |
| 公开算法名称与数学公式 | 复制测试用例数据、示例文案、UI 文案 |
| 「项目 X 用自适应步长保证能量守恒」这类结论 | 复制对方 SVG 图标、Logo、配色、插画、字体 |

判断口诀：**思想无版权，表达有版权**。数学公式与算法步骤属于思想；具体实现、命名、注释、美术、文案属于表达。

## 硬性红线

1. Copyleft 项目零代码、零资源、零文案、零图标、零命名复用。
2. 不新增运行时第三方依赖；若确需新增，先确认 SPDX，再更新 `THIRD_PARTY_NOTICES.md`，并在 CI 加许可证检查。
3. 外部导入的实验包 / 插件必须自带 `meta.license` 与 `meta.attribution`，来源不明直接拒绝入库（见 `scripts/package_check.mjs`）。
4. 包内表达式不得含 `eval` / `new Function` / `require` / `fetch` / `process` 等注入面，必须自写解析器。
5. 不用「翻译式改写」规避许可证——实质性相似仍构成衍生作品。
6. 不把 `NOASSERTION` 当成「无许可证」或「可自由使用」。

## 名称 / 商标风险

- 商标权独立于著作权：即使代码全部自研，近似名称仍可能构成混淆或侵权。
- 检查维度：拼写近似、大小写差异、是否属于同一软件类别、是否已有注册商标。
- 处置：README 写明「本项目与 X 无任何关联、非其官方产品、未使用其代码与商标」；**公开发布前改名**（内部代号可暂留，但对外名称必须区分）。
- 不要在文档、包名、发布标题里用他人产品名做 SEO。

## 合规报告模板要点

`docs/开源项目调研与合规报告.md` 至少包含：

1. 检索方法：关键词组数、端点、时间、限流情况与失败清单。
2. 候选池规模与去重后的数量。
3. 精确核查清单：仓库 / SPDX / 许可证全文文件名 / 交叉验证来源。
4. `NOASSERTION` 专项：官方来源、最终结论、证据链接。
5. 分级矩阵：宽松 / 弱 Copyleft / 强 Copyleft 各自映射到本项目的哪种动作。
6. 硬性规则逐条声明（零依赖、零复用、来源可追溯、名称隔离）。
7. 依赖清单留档：运行时 / 构建期 / 系统级（如 Rust crates）分别列出。
8. 名称风险与后续动作（含未决事项）。
9. 未来合规操作清单：新增依赖、更换许可证、公开发布前各自要做什么。

## THIRD_PARTY_NOTICES.md 结构

1. 运行时直接依赖（名称 / 版本 / SPDX / 用途 / 是否修改）。
2. 构建期依赖（不进入最终产物，但仍列明）。
3. 系统级依赖（如桌面端 crates、移动端 SDK）。
4. 仓库内自带的第三方副本（如有，注明来源与许可；**优先移除**）。
5. **仅作思路参考、未复用任何代码的项目清单**（逐条列出仓库名与参考了什么思想）。
6. Copyleft 红线声明。
7. 未来合规操作清单。

模板见 `assets/THIRD_PARTY_NOTICES.template.md`。
